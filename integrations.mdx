The Royco Day periphery is the integration layer around Royco Day markets. It provides contracts for synchronizing market accounting, exposing tranche prices through Chainlink-compatible interfaces, and wrapping Royco tranches for Pendle.

Source code: [royco-day-periphery on GitHub](https://github.com/roycoprotocol/royco-day-periphery)

## Market Syncer

The Market Syncer keeps mark-to-market accounting current across Royco Day markets without waiting for normal deposits or redemptions. It batches synchronization calls across registered market kernels and can either propagate a failed sync or tolerate it and emit an `AccountingSyncFailed` event.

The syncer is an access-controlled, pausable singleton. Registered kernels are verified against the Royco Factory before they can be added to the sync set.

Key operations:

- `executeBatchAccountingSync(bool tolerateReversions)` synchronizes every registered market.
- `executeBatchAccountingSyncFor(address[] marketKernels, bool tolerateReversions)` synchronizes a selected set of markets.
- `addMarketKernels(address[] marketKernels)` and `removeMarketKernels(address[] marketKernels)` manage the synchronization set.
- `getMarketKernels()` and `isMarketKernelRegistered(address marketKernel)` expose the current registration state.

The deployed Market Syncer address is listed on the [Key Addresses](/key-addresses) page.

## Tranche Price Oracles

The periphery includes permissionless factories that deploy deterministic, Chainlink-compatible price oracles. Each requested tranche is validated against the Royco Factory before an oracle is deployed.

### Tranche NAV Oracle

The Tranche NAV Oracle reports the value of one tranche share in the market's NAV asset, such as USD, BTC, or ETH. It exposes the standard Chainlink AggregatorV3 interface and returns the tranche's current NAV per share.

Use the factory to:

- Deploy an oracle with `deployOracle(address tranche, string navAsset)`.
- Predict its deterministic address with `predictOracleAddress(address tranche, string navAsset)`.
- Read the deployed oracle for a tranche from `trancheToOracle(address tranche)`.

The oracle becomes consumable once the tranche has non-zero supply and non-zero NAV because Chainlink consumers reject non-positive prices.

### Tranche Base Asset Oracle

The Tranche Base Asset Oracle reports the value of one tranche share in the tranche's own base asset. For senior and junior tranches, this is the collateral asset. For liquidity provider tranches, it is the pool token claim; idle liquidity-premium senior shares are excluded from the reported value until reinvestment.

Use the factory to:

- Deploy an oracle with `deployOracle(address tranche)`.
- Predict its deterministic address with `predictOracleAddress(address tranche)`.
- Read the deployed oracle for a tranche from `trancheToOracle(address tranche)`.

### Fundamental Stablecoin Oracle

The Fundamental Stablecoin Oracle wraps an underlying Chainlink-compatible stablecoin feed. Prices at or above a configured minimum peg threshold are reported as exactly one quote asset, while prices below the threshold pass through unchanged so genuine depeg events remain visible.

## Pendle SY Wrapper

The Pendle SY Wrapper turns Royco senior, junior, and liquidity provider tranche shares into Pendle Standardized Yield tokens. This makes tranche yield compatible with Pendle's principal-token and yield-token markets.

Wrapping and unwrapping are one-to-one with the underlying tranche shares. The SY exchange rate is based on the tranche's effective NAV per share, using the market kernel's preview accounting so liquidity-premium accrual is reflected continuously.

The factory deploys each SY behind a transparent upgradeable proxy administered by Pendle's canonical proxy admin. The deployed SY is owned by Pendle's pause controller, as required by Pendle's deployment model.

Use the factory to:

- Deploy an SY for a Royco tranche with `deploySY(address tranche, address offchainRewardManager)`.
- Read the deployed SY proxy from `trancheToOffchainRewardManagerToSY(address tranche, address offchainRewardManager)`.

For a tranche without offchain rewards, use the zero address for `offchainRewardManager`.
